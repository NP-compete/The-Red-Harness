## Question coverage: which tables to use

**ExpenseMaster** answers many question categories—not only "spend"—using one or more table sets in the same database. Each row of the table below can be extended when new data sources are added.

| Question category | Examples | Tables | Schema | `_filter_note` |
|-------------------|----------|--------|--------|----------------|
| **Variance** (actuals vs budget/forecast, overage/underage, overrun) | Sales spend vs budget, PPL Q4 vs BoQ forecast, Marketing Jan vs forecast, which groups overspent on T&E | OneStream, GL | `EXPENSEMASTER_DB.TEST_MARTS` (preferred when both accessible); fallback `EXPENSEMASTER_DB.RHAI_MARTS` | First column; Critical Rule #7 — filters + plan-rate suffix (`amount_usd` / `amount_usd_current_plan_year`). |
| **Load rate & metrics** | Benefits Load Rate (e.g. Q4 Sales vs prior year), Comp/Ben cost per headcount by country | OneStream | `EXPENSEMASTER_DB.TEST_MARTS` (preferred when both accessible); fallback `EXPENSEMASTER_DB.RHAI_MARTS` | First column; Critical Rule #7 — filters + plan-rate suffix. |
| **Spend by department/vendor/account/period/geo** | Total IT spend, total Services spend, spend by T&E category, by geo/region, Learning Cross Charge split by department | GL, OneStream | `EXPENSEMASTER_DB.TEST_MARTS` (preferred when both accessible); fallback `EXPENSEMASTER_DB.RHAI_MARTS` | First column; Critical Rule #7 — filters + plan-rate suffix. |
| **Rankings & top N** | Top vendors (Misc OpEx, Equipment, Marketing, IT, Red Hat–wide), top cost centers by overrun, biggest overspend/underspend areas | GL, OneStream | `EXPENSEMASTER_DB.TEST_MARTS` (preferred when both accessible); fallback `EXPENSEMASTER_DB.RHAI_MARTS` | First column; Critical Rule #7 — filters + plan-rate suffix. |
| **YoY comparison** | Top vendors vs year prior, cost area grown/declined most YtY | GL, OneStream | `EXPENSEMASTER_DB.TEST_MARTS` (preferred when both accessible); fallback `EXPENSEMASTER_DB.RHAI_MARTS` | First column; Critical Rule #7 — filters + plan-rate suffix. |
| **Headcount** | Headcount by department/month, per-HC cost, concentration by country | OneStream headcount | `EXPENSEMASTER_DB.TEST_MARTS` (preferred when both accessible); fallback `EXPENSEMASTER_DB.RHAI_MARTS` | First column; describe filters (Rule #7 style where amounts apply). |
| **IT forecast / future / planning** (IT only) | Future vendor spend (e.g. July 2026), PO termination impact, **IT contract non-renewal / “let expire” forecast savings** (renewal tail in `ITPF_CONTRACT_FORECAST_W_DELEGATION` — [§8.4b](#84b-financial-impact-of-not-renewing-it-contracts-forecast-savings-by-year)), labor extension, spend by spend driver, app/service TCO (e.g. Computers service, ANSI-001, ServiceNow/Skittles project), **cloud forecast / TBM** (AWS/Azure/GCP in Apptio) | ITPF and Apptio TBM tables | `EXPENSEMASTER_DB.RHAI_MARTS` (ITPF_*, APP_SPEND_*, SERVICE_COST_*) — see [IT forecast / future spend (Apptio tables)](#it-forecast--future-spend-apptio-tables) | First column; Critical Rule **Apptio #8** (`_filter_note`); **use `expense_type` in SQL** on ITPF spend (Rule **#9**). |
| **Hyperscaler cloud spend (Cloudability slice, actuals)** | Past-period **cloud** spend by **Amazon** (user may say **AWS**), **Azure** (user may say **Microsoft**), **GCP** (user may say **Google cloud**), **IBM**; by day, **`cost_center_code`**, **`cost_center_department`** (e.g. Sales, Global Engineering), **`account_name`**, billing owner; month/quarter rollups; top **cloud** accounts or cost centers | `CLOUDABILITY_COST_INFO` | `EXPENSEMASTER_DB.RHAI_MARTS` — see [Cloudability cloud spend](#cloudability-cloud-spend-cloudability_cost_info) | First column; **Cloudability `_filter_note`** (see [Critical rules](#-critical-rules) → **Cloudability**) — always **`SUM(period_amount)`**; not GL plan-rate columns. |

**IT department — actuals vs Apptio:** For **booked / historical spend** (e.g. *"What was IT spend in 2025?"*, *"How much did the IT organization spend last quarter?"*) → **`GL_SUB_LEDGER_AGGREGATE`** (default for transaction-level and vendor-backed actuals). Use **`ONESTREAM_FINANCIAL_AGGREGATE`** with `scenario = 'Actual'` when the user needs **FP&A-aligned actual roll-ups** or **variance vs plan** in the same analysis. **Do not route standalone actuals questions to Apptio.** Use **Apptio** when the question is **forecast / future**, **PO or contract planning impact**, **spend-driver or project forecast lines**, or **application / service TCO** (ITPF / TBM), per the row above and dbt YAML.

**Cost type:** GL and OneStream tables contain **OpEx only**. Apptio (ITPF) tables contain **both OpEx and CapEx**; use `EXPENSE_TYPE` in ITPF to filter or report both.

**When in doubt:** **Booked actuals** for any org (**including IT**) → **GL** (detail) or **OneStream** with `scenario = 'Actual'` (FP&A roll-up) — **not Apptio** unless the ask is explicitly forecast/planning/TBM (see IT row above). **Variance, budget, headcount, load rate** → **OneStream/GL** as in the table. **IT forecast, PO/contract planning, spend driver, application/service TCO** → **Apptio** (ITPF/TBM). **Past-period hyperscaler / cloud actuals** (AWS, Azure, GCP, IBM, “cloud spend,” **cloud accounts**) → **`CLOUDABILITY_COST_INFO`** in **`EXPENSEMASTER_DB.RHAI_MARTS`** ; **future / forecast cloud** (IT TBM) → **Apptio**, not Cloudability. **Unqualified top accounts or top vendors** (no cloud or hyperscaler signal) → **GL** [Rankings](#question-coverage-which-tables-to-use) row, not Cloudability. Cloudability is **not** a substitute for **total company** spend with those vendors on **GL**.

**Integration and routing:** The table maps question type → source family. Exact table choice (**USE / DO NOT USE**, stakeholder notes, and **Mandatory filtering** — e.g. `forecast_entry_month` / `period_date` vs `period`, actuals vs forecast on ITPF daily, `snapshot_date` on variance, **SUM(cost)** and OpEx-only on TBM marts) is in **dbt mart YAML**: expensemaster-dbt `docs/` (GL, OneStream), `models/rhai_marts/` (Apptio and **`cloudability_cost_info.yml`** with narrative **`docs/cloudability_cost_info.md`**), or **`apptio-dbt/models/marts/`**. **Snowflake:** GL, OneStream, Apptio, and the **Cloudability-enriched mart** deploy to **`EXPENSEMASTER_DB.RHAI_MARTS`** (e.g. **`CLOUDABILITY_COST_INFO`**). Use this README’s source sections for rules and query templates.
