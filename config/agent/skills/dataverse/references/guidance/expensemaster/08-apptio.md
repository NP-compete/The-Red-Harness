### Apptio

1. **Database & Schema**: Use **`EXPENSEMASTER_DB.RHAI_MARTS`** for all Apptio/ITPF and TBM (APP_*/SERVICE_*) tables.
2. **Latest Forecast Filter**: Always filter to the **most recent forecast version**. **ITPF_FORECAST_DAILY_CURRENT**, **ITPF_LABOR_FORECAST_DAILY**, **ITPF_FORECAST_DAILY_MONTH_VARIANCE**: use `forecast_entry_month = (SELECT MAX(forecast_entry_month) FROM same_table)` (column already on mart). **ITPF_CONTRACT_FORECAST_W_DELEGATION**: the mart may expose only `current_fy_plan_version` — either **`current_fy_plan_version = (SELECT MAX(current_fy_plan_version) FROM same_table)`** (string ordering must match business “latest”), **or** add a CTE that computes **`forecast_entry_month`** from `current_fy_plan_version` with the **same** `DATE_FROM_PARTS` / `REGEXP_SUBSTR` pattern as **`ITPF_FORECAST_DAILY_CURRENT`** (see [§8.4b](#84b-financial-impact-of-not-renewing-it-contracts-forecast-savings-by-year)), then **`forecast_entry_month = (SELECT MAX(forecast_entry_month) FROM that CTE)`**. **ITPF_CONTRACT_FORECAST_W_DELEGATION** uses **`current_fy_plan_version`** on joins to detail tables per YAML. APP_* / SERVICE_* tables do **not** use a forecast filter.
3. **Period Filtering**: Always use `period_date` (DATE type) instead of `period` (TEXT) for filtering. Use `period_date >= DATE_TRUNC('month', CURRENT_DATE())` for future only; `period_date < CURRENT_DATE()` for actuals.
4. **OpEx/CapEx Disclosure**: When returning amounts from ITPF tables, **always** note what portion is OpEx vs CapEx in your response (use **`expense_type`**). Use **`expense_type` in the SQL** per **Rule #9** — narrative alone is not enough.
5. **C&B Limitation**: C&B (labor costs) are **NOT** forecast beyond the current fiscal year. Never say "costs dropped" when C&B shows $0 in future years. Identify via `ACCOUNT_GROUP = 'C&B'`. For labor cost from ITPF_LABOR_FORECAST_DAILY use `(SUM(base_compensation/12))/COUNT(DISTINCT period_date)` for monthly cost, not `PERIOD_AMOUNT`.
6. **Data Source Hierarchy**: For prior months, ITPF Forecast Daily Current supersedes ITPF Contract Forecast w Delegation (Contract has original forecasted amounts; Daily Current has actuals).
7. **IT-only scope; actuals routing**: Apptio tables only include **IT** planning and TBM views — not other departments. **Booked IT actuals** (e.g. total IT spend for a past or closed period) → **GL** or **OneStream Actual** — **not** Apptio. Use Apptio for **forecast**, **future periods**, planning dimensions, or **modeled** app/service TCO as in the [Apptio section](#it-forecast--future-spend-apptio-tables). For non-IT spend use GL/OneStream.
8. **`_filter_note` (Apptio spend)**: On **Apptio spend queries**, set **`_filter_note` as the FIRST column** to exactly: **`'Using Apptio data, which includes spend that resides in IT cost centers.'`** Do not add filter/version details to `_filter_note` for Apptio. (GL/OneStream still use Rule #7 with plan-rate wording.)
9. **REQUIRED: use `expense_type` on every ITPF spend query**: Any Apptio **ITPF** query that returns dollar amounts — including **“total spend”** asks must **use `expense_type` in the SQL** so OpEx and CapEx are visible; do **not** return one opaque combined total. **Valid patterns:** (a) **`expense_type` in `SELECT`/`GROUP BY`** — separate rows per type ([§8.0](#80-total-it-vendor-spend-future-month)); (b) **`SUM(CASE WHEN expense_type = 'OpEx' …)`** / **`'CapEx'`** — separate columns ([§8.6](#86-spend-driver-analysis)); (c) **`WHERE expense_type = …`** when the ask is OpEx-only or CapEx-only. On **`ITPF_CONTRACT_FORECAST_W_DELEGATION`**, use **`account_expense_type`** the same way. Skip only when the user explicitly wants a single combined number with **no** OpEx/CapEx split.
